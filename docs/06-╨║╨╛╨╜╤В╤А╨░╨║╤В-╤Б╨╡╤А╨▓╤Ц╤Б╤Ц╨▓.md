# 6. Контракт сервісів (лекція 11)

Контракт описує інтерфейс сервісу, вхідні й вихідні параметри та можливі помилки. Усі тіла запитів і відповідей у JSON, імена полів у `snake_case`.

## Постачальники, споживачі, реєстр

| Роль | Хто виконує |
|---|---|
| Постачальник авторизації | auth-service |
| Постачальник HTTP API рахунків і переказів | transfer-service |
| Споживач HTTP API | операціоніст, аналітик, load-generator, Prometheus (`/metrics`) |
| Постачальник подій | transfer-service |
| Споживач подій | fraud-worker |
| Реєстр сервісів | внутрішній DNS Docker: сервіси знаходять один одного за назвою, наприклад `rabbitmq`, `postgres` |

## auth-service

Базова адреса: `http://localhost:8002`

### POST /login

| Поле | Тип | Обов'язкове |
|---|---|---|
| `username` | рядок | так |
| `password` | рядок | так |

Відповідь 200:

```json
{ "access_token": "<JWT>", "token_type": "Bearer", "expires_in": 7200, "role": "operator" }
```

Токен підписано HMAC-SHA256, видавець `bank-auth`, вміст: `sub` (логін), `role`, `jti`, `exp`.

| Код | Причина |
|---|---|
| 400 | немає логіна або пароля |
| 401 | неправильний логін або пароль |
| 403 | користувача вимкнено |

### POST /register (роль admin)

| Поле | Тип | Умова |
|---|---|---|
| `username` | рядок | 3–50 символів |
| `password` | рядок | 8–128 символів |
| `role` | рядок | `operator` (типово), `analyst`, `admin` |

Коди: 201 створено, 400 неправильні дані, 401 немає токена, 403 не адміністратор, 409 користувач існує.

### Інші

| Метод | Шлях | Роль | Відповідь |
|---|---|---|---|
| GET | `/verify` | будь-яка | `username`, `role` |
| GET | `/users` | admin | список користувачів без хешів |
| POST | `/users/{username}/disable` | admin | вимикає вхід |
| POST | `/users/{username}/enable` | admin | вмикає вхід |
| GET | `/health`, `/metrics` | без токена | стан, метрики Prometheus |

## transfer-service

Базова адреса: `http://localhost:8000`. Усі шляхи `/api/*` вимагають заголовок `Authorization: Bearer <JWT>`; без нього 401, з неправильною роллю 403.

| Метод | Шлях | Ролі | Опис |
|---|---|---|---|
| GET | `/api/accounts?limit=100` | operator, analyst, admin | список рахунків |
| GET | `/api/accounts/{id}` | operator, analyst, admin | рахунок або 404 |
| POST | `/api/accounts` | operator, admin | відкрити рахунок |
| POST | `/api/accounts/{id}/unblock` | admin | розблокувати рахунок |
| POST | `/api/transfers` | operator, admin | виконати переказ |
| GET | `/api/transfers?account_id=&limit=50` | operator, analyst, admin | історія переказів |
| GET | `/api/transfers/{id}` | operator, analyst, admin | переказ зі статусом антифроду |
| GET | `/api/fraud-alerts?account_id=&limit=50` | analyst, admin | спрацьовані правила |
| GET | `/api/stats` | operator, analyst, admin | кількість рахунків, переказів, алертів |
| GET | `/health`, `/metrics` | без токена | стан, метрики |

### POST /api/accounts

| Поле | Тип | Умова |
|---|---|---|
| `owner_name` | рядок | 1–100 символів |
| `initial_balance` | число | 0–10 000 000, типово 0 |
| `currency` | рядок | `UAH` (типово), `USD`, `EUR` |

Відповідь 201: рахунок з `id`, `iban`, `balance`, `is_blocked`, `is_internal`.

### POST /api/transfers

| Поле | Тип | Умова |
|---|---|---|
| `from_account_id` | ціле | обов'язкове |
| `to_account_id` | ціле | обов'язкове, не дорівнює `from_account_id` |
| `amount` | число | більше 0, не більше 1 000 000, не більше 2 знаків після коми |
| `reference` | рядок | необов'язкове, призначення платежу |

Необов'язкові заголовки для дослідження транзакцій (типові значення з `docker-compose.yml`):

| Заголовок | Значення | Типово |
|---|---|---|
| `X-Isolation-Level` | `read-committed`, `repeatable-read`, `serializable` | `read-committed` |
| `X-Lock-Mode` | `ordered` (FOR UPDATE за зростанням id), `naive` (FOR UPDATE у порядку запиту), `none` (без блокувань) | `ordered` |
| `X-Lock-Hold-Ms` | 0–3000, пауза між блокуванням двох рахунків | 0 |
| `X-Max-Retries` | 0–5, повтори після deadlock або 40001 | 0 |

Відповідь 201:

```json
{
  "id": "8d3e6f9e-78ea-4810-a077-d5dd1d491756",
  "from_account_id": 7, "to_account_id": 8, "amount": 150.25, "currency": "UAH",
  "status": "completed", "fraud_status": "pending",
  "from_balance_after": 61476.54, "to_balance_after": 98012.10,
  "isolation_level": "read-committed", "lock_mode": "ordered", "attempts": 1,
  "created_at": "2026-11-20T17:14:48.061Z"
}
```

| Код | `error` | Причина |
|---|---|---|
| 400 | `invalid_request` | немає рахунків або тіло некоректне |
| 400 | `invalid_amount` | сума поза межами або більше 2 знаків після коми |
| 400 | `same_account` | переказ на той самий рахунок |
| 400 | — | неправильне значення заголовка `X-*` |
| 401 | — | немає дійсного токена |
| 403 | — | роль не має права на переказ |
| 403 | `account_blocked` | рахунок заблоковано антифродом |
| 404 | `account_not_found` | рахунку не існує |
| 409 | `deadlock_detected` | SQLSTATE 40P01, транзакцію відкочено, можна повторити |
| 409 | `serialization_failure` | SQLSTATE 40001, транзакцію відкочено, можна повторити |
| 422 | `insufficient_funds` | недостатньо коштів |
| 422 | `currency_mismatch` | різні валюти рахунків |
| 503 | `database_unavailable` | PostgreSQL недоступний |
| 500 | `internal_error` | інша помилка |

## Подія TransferInitiated

| Параметр | Значення |
|---|---|
| Virtual host | `bank` |
| Exchange | `bank` (topic) |
| Ключ маршрутизації | `transfer.initiated` |
| Черга | `transfers.fraud-check` |
| Тіло | JSON, див. `02-архітектура.md` |
| Заголовки | `message_id`, `type`, `traceparent`, persistent |
| Гарантія | publisher confirms; ручне підтвердження споживачем |
| Помилка формату | `nack` без повтору → `bank.dead` → `transfers.invalid` |
| Помилка бази | `nack` з поверненням у чергу через 2 с |
| Повторна доставка | переказ уже не `pending` → лише `ack` |

## fraud-worker

HTTP лише для моніторингу: `GET /health`, `GET /metrics` на порту 8001.

### Правила антифроду

Налаштовуються змінними середовища в `docker-compose.yml`.

| Правило | Умова | Бал |
|---|---|---|
| `high_amount` | сума ≥ `HIGH_AMOUNT_THRESHOLD` (50 000) | 40 |
| `velocity` | ≥ `VELOCITY_MAX_TRANSFERS` (5) переказів з рахунку за `VELOCITY_WINDOW_SECONDS` (60 с) | 35 |
| `ping_pong` | зворотні перекази B→A за `PING_PONG_WINDOW_SECONDS` (300 с) | 30 за кожен, до 60 |
| `fan_out` | ≥ `FAN_OUT_MAX_RECIPIENTS` (4) різних отримувачів за `FAN_OUT_WINDOW_SECONDS` (300 с) | 25 |
| `balance_drain` | переказ ≥ `DRAIN_RATIO` (90 %) балансу і ≥ 1000 | 25 |
| `round_amount` | кругла сума ≥ 10 000, кратна 1000 | 10 |

Бал обмежено 100. Бал ≥ `SUSPICIOUS_SCORE` (50): `suspicious`, правила записуються у `fraud_alerts`. Бал ≥ `BLOCK_SCORE` (80): рахунок відправника блокується. Перекази між двома внутрішніми рахунками (`is_internal`) не перевіряються.

Sweeper кожні `SWEEP_INTERVAL_SECONDS` (15 с) перевіряє перекази, що залишились `pending` довше `SWEEP_AGE_SECONDS` (60 с).
