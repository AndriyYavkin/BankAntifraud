# 3. Тестування

Тести виконано 20 листопада 2026 року автоматизованим скриптом через HTTP API, `psql` і `rabbitmqctl`. Сервіси запускались з тими самими збірками C# (.NET 8), PostgreSQL 16, Prometheus 2.55.1, Loki 3.1.1, Tempo 2.9.0 і Alloy 1.5.1, що й у `docker-compose.yml`, але без Docker (RabbitMQ 3.12 замість 4.0). Перед захистом треба повторити ключові тести в Docker Desktop (розділ «Перевірка в Docker» нижче) і додати скриншоти.

## Пояснення до тестів конкурентного доступу

| Тест | Налаштування | Що відбувається |
|---|---|---|
| Т-23 | `X-Lock-Mode: naive`, `X-Lock-Hold-Ms: 300` | транзакція 1 блокує A і чекає B, транзакція 2 блокує B і чекає A; PostgreSQL через `deadlock_timeout` (1 с) скасовує одну з них |
| Т-24 | `ordered` | обидві транзакції блокують спочатку менший id, друга чекає першу, deadlock неможливий |
| Т-25 | `naive` + `X-Max-Retries: 3` | deadlock відбувається, але сервіс повторює транзакцію і клієнт отримує 201 |
| Т-26 | `none` + `READ COMMITTED` | баланс читається без блокування, обидві транзакції записують «старе значення мінус сума»: списання губиться, гроші з'являються нізвідки |
| Т-27, Т-28 | `none` + `SERIALIZABLE` або `REPEATABLE READ` | PostgreSQL виявляє паралельне оновлення рядка і скасовує транзакцію з SQLSTATE 40001 |
| Т-29 | `ordered` + `READ COMMITTED` | `FOR UPDATE` усуває втрачене оновлення навіть на найслабшому рівні ізоляції |

## Перевірка в Docker (виконати перед захистом)

| № | Що перевіряємо | Дія | Очікування |
|---|---|---|---|
| Д-1 | Запуск | `docker compose up -d --build`, `docker compose ps` | усі контейнери `running`, `postgres` і `rabbitmq` `healthy` |
| Д-2 | Цілі Prometheus | http://localhost:9090/targets | 8 цілей `UP` |
| Д-3 | Дашборд | увійти в Grafana, запустити `mixed --duration 120` | усі панелі з даними |
| Д-4 | Deadlock | `deadlock --count 10` | 409 у відповідях, алерти `DeadlocksDetected`, `PostgresDeadlocks` |
| Д-5 | Втрачене оновлення | `lost-update --count 10` | `INCONSISTENT`, алерт `TotalBalanceChanged` |
| Д-6 | Шахрайство | `fraud` | 403 `account_blocked` у кінці, алерт `AccountBlockedByAntiFraud` |
| Д-7 | Логи | Explore → Loki → `{service="postgres"} \|= "deadlock"` | рядки `ERROR: deadlock detected` з `DETAIL` |
| Д-8 | Трейси | Explore → Tempo → `{resource.service.name="transfer-service"}` | трейс зі спанами transfer-service і fraud-worker |
| Д-9 | Зупинка воркера | `docker compose stop fraud-worker`, `normal --count 20` | черга росте, через 30 с алерт `FraudWorkerDown` |
| Д-10 | Вхід у Grafana | відкрити http://localhost:3000 у приватному вікні | сторінка входу, без пароля даних не видно |

Рівні тестування за лекцією 3: Т-1…Т-22 перевіряють окремий сервіс, Т-23…Т-38 перевіряють взаємодію сервісів, бази та брокера.

Зв'язок тестів із вимогами наведено в `07-трасування.md`.
